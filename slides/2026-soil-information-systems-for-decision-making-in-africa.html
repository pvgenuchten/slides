FAIR principles

The FAIR principles provide a governance framework for data, from a reuse perspective:

  • Findable
  • Accessible
  • Interoperable
  • Reusable

Soil data specifics

  • legacy data and formats
  • interaction with many other domains (agriculture, pollution, carbon sequestration, build environment, hydrology)
  • Management practices & LTE
  • large number of soil indicators
  • long history of (local) practices

Findable data

Rich metadata searchable via a catalogue

What is a dataset?

  • civil cervant: a database which is continuously updated, exposed via an API
  • academic: a validated collection of records at a given point in time, which I can uniquely reference in my publication

Datasets as a source for digital soil mapping (DSM)

  • DSM is the process of prediction of soil property distribution in space and time
  • DSM efforts happen irragularly, based on latest snapshots of source data and covariates
  • data from the own organisation as well as remote sources
  • the academic view on dataset is more appropriate for DSM

Use of repositories

  • Easy to find and reference
  • Find today, find in 10 years time
  • Common data and knowledge repositories offer persitent storage over time
  • Aggregators (openaire, google) harvest from repositories to optimize findability

Persistent Identification is an aspect of findability (identifiers)

  • datasets should be uniquely identified (uuid)

  • Strong push to adopt identification platforms such as DOI and Handle.net

  • Proper identification facilitates citation from reports/scientific articles

  • For large data, or specific use cases (map vizualisation), data can also be shared using an api or web service, but it complicates identification

Accessible data

  • Data is made available through an open protocol (http)
  • Metadata should still exist, even if the data itself is discarded
  • Metadata Public; Data public, protected or internal

Tiered access and national stewardship

  • As open as possible, as closed as necessary
  • As data steward you should have control on access to the data, even when handed over to a secondary hosting provider (repository)
  • Alternatively author the DOI of the data, arbitrary where the data is hosted
  • Ultimately the enclosed metadata indicates the usage restrictions of the data

Role of common vocabularies

  • The use of common multi-lingual vocabularies provide a mechanism to describe data using universal definitions
  • Common vocabularies such as Agrovoc, WRB, GLOSIS, ISO11074, GEMET
  • Use Agrovoc terms as keywords in metadata
  • Describe columns in a dataset using terms from GLOSIS
  • Express unit of measure using QUDT concepts

Reusable data

  • Describe the provenance of the data, so potential users understand if and how they can use the data.
  • Apply a relevant license; as open as possible, as closed as necessary

Describe a dataset using rich metadata for findability and resuability

  • Generic properties are covered in most metadata models
  • Metadata model can be extended by adding a metadata sidecar file (RO-Crate approach)

Use of common repositories

  • Common repositories, such as Zenodo, OSF, Pangaea, Dataverse, offer many of the FAIR principles by default

  • As a contributor you are owner of the data

  • Data can be published with tiered access

  • Funders may endorse the use of a certain repository

  • Understand the jurisdiction of the country where the repository is hosted

  • Consider the reliability of the repository (timespan 20-50 years)

Some data publication samples

  • Kenya SIS

Data aggregators are not a good fit for publishing your data

  • Various soil data aggregators exist, which harmonize and clean soil data
  • Examples such as ISRIC, ISDA, Varda
  • The aggregators are able to make good soil maps
  • Data contributed to an aggregator is out of your control
  • Instead publish the data in a repository and share the DOI with the aggregator
  • The feedback from the aggregator about your data is actually very useful, make sure to retrieve it

Frameworks to support implementation

  • Cabi and Gates foundation prepared a framework to put the FAIR principles in action in the environmental domain.
  • Cabi, ISRIC and Gates foundation also prepared a framework for Soil Information System design.
  • The SIS framwork includes some case studies from various African countries.

Conclusions

  • Data governance is a wide topic, interoperability is an important pillar
  • FAIR principles provide a framework for governance focussed on reuse
  • Soil data is special for its specific use cases, interaction with many domains and long time span
  • Harmonization is important, but do not replace the source data

More details on data governance

The extra slides provide some details on the topic of data governance

Roles, Responsibilities, and Accountability

  • Define who owns, stewards, custodians, and uses data.
  • Establish decision-making bodies (e.g. data governance boards).
  • Clarify responsibilities across ministries, agencies, and local governments.

Data Quality and Lifecycle Management

  • Ensure data is accurate, complete, consistent, timely, and fit for purpose.
  • Define standards for data collection, validation, maintenance, archival, and disposal.
  • Monitor and improve data quality through metrics and audits.

Policies, Standards, and Interoperability

  • Develop common data standards, metadata, reference data, and vocabularies.
  • Promote interoperability between government systems.
  • Standardize formats, identifiers, APIs, and data models to enable data sharing

Security, Privacy, and Legal Compliance

  • Protect sensitive and personal information.
  • Comply with relevant legislation (e.g. GDPR, freedom of information laws, records management requirements).
  • Define access controls, classification schemes, and procedures for handling breaches.

Tiered access

User Level of access
General public Aggregated statistics, maps, open datasets
Researchers Detailed but anonymized observations under a data-sharing agreement
Government agencies Full datasets needed for regulatory or policy purposes
Data stewards Ability to edit, correct, and approve records
System administrators Technical access to the platform, but not necessarily permission to use the data analytically

Tiered access supports governance objectives

  • Privacy and confidentiality: Protects personal, commercially sensitive, or nationally sensitive information.
  • Legal compliance: Helps meet obligations under regulations such as GDPR, freedom of information laws, or sector-specific legislation.
  • Data integrity: Limits editing rights to authorized users, reducing the risk of accidental or unauthorized changes.
  • Need-to-know principle: Users receive only the information necessary for their role.
  • Encouraging openness: Governments can publish as much data as possible while still protecting restricted information.

Data Sharing, Access, and Value Creation

  • Establish policies and agreements for sharing data within government and with external stakeholders.
  • Balance openness with confidentiality through open data, licensing, and access controls.
  • Promote reuse of data for evidence-based policymaking, service delivery, transparency, and research.

These five aspects are often supported by cross-cutting activities such as:

  • Metadata management
  • Master and reference data management
  • Risk management
  • Training and capacity building
  • Monitoring, compliance, and continuous improvement
